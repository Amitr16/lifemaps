# Render Database Migration Instructions

## Admin Tables Migration

This document explains how to run the admin tables migration on Render.com.

### What This Migration Does

Creates the following database tables:
- `super_admin` - For super admin accounts
- `admin` - For regular admin accounts
- Adds `admin_id` column to `user` table
- Creates default super admin account (username: `superadmin`, password: `superadmin123`)

### Method 1: Using Render Shell (Recommended)

1. Go to your Render dashboard
2. Navigate to your backend service
3. Click on "Shell" tab
4. Run the following command:
   ```bash
   cd backend && node scripts/migrate-admin-tables.js
   ```

### Method 2: Using Build Command

1. Go to your Render dashboard
2. Navigate to your backend service
3. Go to "Settings" -> "Build & Deploy"
4. Add this to your "Build Command":
   ```bash
   npm install && npm run migrate:admin && npm run build
   ```
   (Note: This runs migration on every deploy. Use Method 1 for one-time migration.)

### Method 3: Using Render Database Console

1. Go to your Render dashboard
2. Navigate to your PostgreSQL database
3. Click on "Connect" -> "PSQL"
4. Copy and paste the contents of `backend/scripts/2025-01-31_create_admin_tables.sql`
5. **Important**: Replace the INSERT statement with the bcrypt hash generated by the Node.js script

### Verification

After running the migration, verify it worked:

```sql
-- Check if tables exist
SELECT table_name FROM information_schema.tables 
WHERE table_schema = 'public' 
AND table_name IN ('super_admin', 'admin');

-- Check if super admin exists
SELECT id, username FROM super_admin WHERE username = 'superadmin';

-- Check if admin_id column exists in user table
SELECT column_name FROM information_schema.columns 
WHERE table_name = 'user' AND column_name = 'admin_id';
```

### Troubleshooting

**Error: "relation already exists"**
- This is normal if tables already exist. The script handles this gracefully.

**Error: "function update_updated_at_column() does not exist"**
- Run this first:
  ```sql
  CREATE OR REPLACE FUNCTION update_updated_at_column()
  RETURNS TRIGGER AS $$
  BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
  END;
  $$ LANGUAGE plpgsql;
  ```

**Error: Connection timeout**
- Make sure your database is running and accessible
- Check your environment variables (DB_HOST, DB_NAME, DB_USER, DB_PASSWORD)
